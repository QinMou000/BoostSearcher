# 启动时同步外部文章到本地语料

## 背景

当前 `http_server` 在启动时读取 `./data/raw.txt` 建立内存索引，然后开始监听端口。原始 Markdown 位于 `data/raw/md/`，由独立的 `parser` 程序汇总为 `data/raw.txt`。用户希望先验证一个可独立运行的 Python 程序，再决定是否由 HTTP 服务每天凌晨调用它。

## 已确认的事实

- `engine/src/http_server.cc` 在 `Searcher::InitSearcher` 后才调用 `listen`，当前没有后台任务或索引热更新机制。
- `engine/src/parser.cc` 会递归读取 `data/raw/md/` 并整体重写 `data/raw.txt`，但它是独立可执行程序，当前没有可被 HTTP 服务直接复用的库接口。
- `engine/src/index.cpp` 只从 `data/raw.txt` 建立一次内存索引；正在服务的 `Searcher` 不会感知之后写入的 Markdown 文件。
- Gitee 仓库 `wang-qin928/personal_post` 是公开仓库，默认分支为 `main`，`source/_posts` 下已有 190 篇 Markdown；本地 `data/raw/md/` 当前有 185 个文件。
- 个人站点是已渲染的静态页面；其文章链接适合展示，不是稳定的 Markdown 同步接口。

## 本轮交付

实现一个可独立启动的 Python 同步工具，不修改 `http_server`。工具默认真实同步到 `data/raw/md/`，并可通过 `--output-dir` 指定任意输出目录；显式传入 `--dry-run` 才只预览。这能在不修改现有服务和索引的前提下验证远端枚举、去重、下载和落盘行为。

## 功能范围

1. 通过 Gitee API 枚举 `main` 分支 `source/_posts/` 下的 Markdown 文件；原始下载地址受限时，回退到同路径 Contents API 获取 Base64 正文。
2. 以远端相对路径映射到 `data/raw/md/` 下的目标文件，并用 Gitee 返回的 Git Blob SHA 与本地内容比较：本地 Markdown 先把 CRLF 规范化为 LF，SHA 一致时跳过，不一致时以远端版本原子替换本地文件。
3. 默认真实下载和更新；`--dry-run` 模式只预览新增和更新文章。
4. 内容先写入同目录临时文件，再以不覆盖已有文件的原子方式发布，防止残缺 Markdown 可见。
5. 固定允许的 HTTPS 主机、仓库、分支、源目录和 `.md` 扩展名；限制请求超时、单篇体积、单次新增数量与受控并发数。
6. 输出总数、待下载数、已跳过数、成功数和失败原因，并以退出码体现是否有失败。
7. 提供标准库 `unittest` 自动化测试，覆盖预览、下载、重复同步、无效远端记录、网络失败和超大内容。

## 不在本轮范围

- 解析 GitHub Pages 的渲染后 HTML。
- 定时轮询、Webhook、账号鉴权或同步删除远端已删除文章。
- 保留本地优先的冲突解决策略；本轮以远端 Gitee 仓库为文章内容的唯一权威来源。
- `http_server` 启动时执行 Python、每天凌晨调度、子进程管理。
- 同步后自动运行 `parser` 或在服务运行中热更新倒排索引。

## 技术选型

| 项目 | 选择 | 理由 | 风险 |
| --- | --- | --- | --- |
| 同步源 | Gitee V5 Contents API 加原始地址 | 目录接口枚举，原始地址优先；受限时回退到同路径 Contents API | API 限流或服务短暂不可用 |
| 实现语言 | Python 标准库与受控线程池 | 无第三方依赖，可独立启动、单元测试和加速首次全量同步 | 后续需明确 C++ 服务如何调度 Python |
| 更新判定 | Git Blob SHA 比较 | 缺失时新增，远端修订时自动更新，无需额外同步清单 | 远端仓库成为同路径文章的唯一权威来源 |
| 写入方式 | 临时文件后原子发布 | 避免读到下载一半的文件 | 需验证 Windows 和 Linux 文件系统行为 |
| 默认模式 | 真实同步 | 独立执行时直接完成同步目标 | 首次运行应通过 `--output-dir` 指向试验目录 |

## 风险与约束

- 并发：若未来调度程序与人工同步同时运行，写入前必须重新检查本地 SHA；内容一致则跳过，否则以完整的远端版本原子替换。
- 边界：仅接受白名单 HTTPS 地址、预期目录、Markdown 扩展名；拒绝路径回退和异常体积。
- 性能：远端目录只请求一次；逐篇下载采用受控并发，并有明确上限与超时，避免首次全量同步过慢或占满资源。
- 安全：远端内容仅以文本保存，绝不执行；原始和备用下载地址均必须验证来源主机、仓库路径和 Blob SHA。
- 可观测性：命令输出必须让定时任务日志可以直接判断本次是否有新增和失败。

## 后续集成决策

用户确认工具效果后，再决定由 `http_server` 还是系统计划任务在每天凌晨执行。届时还需确认新增文章是否要求同一次服务运行中立刻参与搜索：当前架构需要额外的线程安全索引重建与切换才能实现热更新。

## 验收标准

1. 不传参数时，工具真实下载到默认输出目录；`--dry-run` 时只输出待同步文章且不修改输出目录。
2. 使用 `--output-dir` 时，缺失文章会新增，远端修订过的已有文章会更新；内容 SHA 一致的文章不会重复下载或写入。
3. 下载或写入失败不会产生可被解析器读取的残缺 Markdown 文件。
4. 非白名单下载地址、路径回退、非 Markdown 和超大内容都被拒绝。
5. 自动化测试可重复验证正常、重复、失败和边界场景。
